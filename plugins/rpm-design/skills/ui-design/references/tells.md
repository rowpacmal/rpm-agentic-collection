# AI-template tells

These are defaults generated UIs fall into. Avoid them unless the brief or `DESIGN.md` asks for one. Then use it on purpose, once.

| Tell | Instead |
|---|---|
| Purple-to-blue or indigo gradients, gradient text, gradient blobs | Flat brand colors, or one real image |
| Small uppercase letter-spaced "eyebrow" labels or pill badges above headings | Put the information in the heading, or cut it |
| A row of identical icon-topped feature cards | A composition that fits the content: a list, a comparison, a real product fragment |
| Cards nested inside cards; a 1px border plus a shadow on everything | A tone step between surfaces. Shadows only on things that float (menus, dialogs) |
| Glassmorphism panels and floating pill navbars | A plain bar: logo, a few links, one action |
| Emoji as icons; decorative dots and sparkles | A consistent icon set, or no icon |
| One italic, serif, or colored "accent" word inside a headline | One face and one color. Let the words carry the emphasis |
| `01 / 02 / 03` index numbering, monospace labels outside code | Order by position or a real ordered list. Use the text face |
| Centered everything; hero with a headline, subline, and two buttons over a blurred gradient | Left-aligned by default. Lead with the strongest real thing (product, photo, number) |
| Generic stock copy ("Unlock the power of…", "Seamless", "Revolutionize") | Concrete claims about this product, in the user's words |
| The same soft 12–16px radius on every element | Choose square or fully round per role and keep it consistent |
| Low-contrast grey body text | Full-contrast ink for running text |

For an app screen (Operate mode), platform conventions beat novelty. Standard tables, forms, and navigation are correct there. They aren't tells.
